# CHRONO CIRCUIT v0.9 — Modular Math
## Technical change specification · Approved revision 1 · 18 September 2026

**Status: Approved and implemented for v0.9.0.** Verification evidence and remaining browser/device checks are recorded in [v0.9 verification](../verification/v0.9.md). The historical baseline below identifies the design intake, not the current HEAD.

## 1. Objective and scope
Decouple the eight-stage action game from its time curriculum. An adult chooses the practice content; the same gates, stages, hazards, bosses, and rewards support it. Initially offer **Time** and **Subtraction: missing numbers**, individually or together. Future subjects must be addable through a small module interface rather than another rewrite of gate progression.

User requirements: four subtraction types; whole-number values and answers; no multiple-choice questions; randomized allocation across gates; remove misleading time-learning descriptions when Time is not selected. Preserve all eight stages and three gates per stage. Gate question count remains 1–10, default 2, fixed for each stage run.

This release does not add other arithmetic subjects, custom question imports, accounts, multiplayer, or new levels.

## 3. Adult configuration
Add a **Math practice** section to the existing protected Adult Settings:
1. Subject checkboxes: Time; Subtraction: missing numbers. Require at least one.
2. When Subtraction is checked, show four independently selectable types, all checked initially:
   - Missing starting number — equation (missing minuend).
   - Missing amount taken away — equation (missing subtrahend).
   - Missing starting number — word problem.
   - Missing amount taken away — word problem.
3. Number range: proposed presets **within 20**, **within 100** (default), **within 1,000**. Range means every displayed value AND the unknown answer is between 0 and the selected maximum.
4. **Include zero** toggle, proposed default off. When off, both parts and the remainder are positive. When on, zero is valid; avoid overrepresenting trivial zero examples.
5. Preserve answer mode, stage answer-mode overrides, question count, adult lock and all other settings.

Add touch/click-accessible ? help explaining missing starting number versus missing amount taken away, number range, randomized distribution, and when changes take effect. Hide irrelevant controls without deleting their saved values. Reject an empty subtraction type selection when Subtraction is enabled. Validation must preserve other edits.

Existing installations and fresh default configuration remain Time-only until an adult chooses Subtraction. Selecting Subtraction enables all four types; the adult can uncheck Time for subtraction-only practice. No silent switch for existing users.

Configuration changes apply to **new stage runs and new Practice Relays**. Continue resumes its original configuration. Stage select must distinguish “Continue: [saved content]” from “New run: [current settings]”. Provide the existing explicit restart action for applying changes now, explaining that current-stage gate work restarts while permanent powers and records remain.

## 4. Exact subtraction contract
Represent every item with M − S = D, where M is the minuend, S the subtrahend, and D the difference. All three are integers satisfying 0 ≤ S ≤ M ≤ maximum and D = M − S.

| Type | Student example | Expected answer | Worked method |
| --- | --- | --- | --- |
| Missing minuend equation | □ − 7 = 12 | 19 | 12 + 7 = 19; check 19 − 7 = 12 |
| Missing subtrahend equation | 19 − □ = 12 | 7 | 19 − 12 = 7; check 19 − 7 = 12 |
| Missing minuend word problem | A box had some bolts. Tempo used 7 bolts. There are 12 bolts left. How many bolts were in the box at first? | 19 | Starting amount = used + left |
| Missing subtrahend word problem | A box held 19 bolts. Tempo used some bolts. There are 12 bolts left. How many bolts did Tempo use? | 7 | Used amount = starting amount − left |

Show a blank box rather than introducing algebraic notation as an extra requirement. Word problems initially show only the story and answer field; revealing the matching equation belongs to a hint or worked solution, preserving the reading task.

Generate valid triples first, then render the selected type. Do not generate independent values and repair invalid arithmetic afterward. No negative answers, decimals, fractions, rounding, multi-step stories, missing differences, or disguised elapsed-time tasks in this module.

Provide at least six distinct short story templates per word-problem type, with countable familiar objects, clear quantities, consistent units and singular/plural grammar. Include ordinary and game-themed contexts. Require no outside facts. Vary numbers and sentence patterns, not only names.

Answer entry is one initially empty numeric field, with visible units outside the field when applicable. Support touch numeric keyboard and desktop digits, Backspace, and Enter. Trim surrounding whitespace, accept leading zeros, and validate the entire entry as digits representing a safe whole number; reject blank, signs, decimal points, exponent notation, fractions, and mixed text. Zero must not be confused with blank. Invalid formatting does not consume a mathematical attempt; a well-formed wrong number does. No answer choices or prefilled answer.

## 5. Allocation and reproducibility
A stage run contains 3 × questionsPerGate original question slots. Fill slots from a seeded shuffled bag of enabled types, so each type occurs before repetition where the slot count allows. A gate may contain different types. With all four types and the default six slots, each type appears at least once; the extra two vary. With only three slots, all four cannot appear; do not claim otherwise or increase the adult’s question count.

For mixed Time + Subtraction, use a balanced subject bag first, then a balanced subtraction-type bag for subtraction slots. Time slots retain the current stage’s time curriculum. Time-only retains existing stage-specific allocation and compatible legacy generation.

Persist a run seed and configuration snapshot; reconstruct exactly the same questions after gate exit, death, reload, and export/import. Seed inputs include stage/run identity, gate/slot, subject, type and generator version. Fresh runs use a new seed and should avoid immediately repeating the same numerical problem when alternatives exist. No guarantee of forever-unique random problems.

A fresh check after a demonstration or a Mastery answer stays on the **same type and range**, with a genuinely different numerical triple, not merely renamed objects. Seed checks separately; preserve their state through reloads. Exhaustion handling must never loop indefinitely.

## 6. Module architecture and source impact
Introduce a registry and shared task interface, using small ES modules and relative imports; no framework or paid/network dependency.

Suggested files: public/math-modules.js, public/subtraction.js, public/practice-config.js. Preserve the existing time engine behind a Time adapter.

Each module supplies:
- Stable module/type IDs; adult labels and supported representations.
- Configuration validation and deterministic generation.
- Expected answer, strict parsing/checking, answer label.
- Hint, worked example, fresh same-type check, narration.
- Report skill ID and applicable evidence metadata.

Common generated task fields: id, moduleId, typeId, generatorVersion, seed, templateId, representation, prompt, answer specification, and domain data. Subtraction domain data contains M, S, D and unknown role. Keep expected answers internal to local generation; do not display them before the mode permits.

Gate reward/effect text belongs to the gate, not to the selected question template. Preserve machinery changes and reward wording when replacing its math. Existing ID-prefix cleanup assumptions must be replaced or supported explicitly so replay clears only the intended stage’s answers/sessions.

## 7. Other time dependencies and their intended behavior
- **Stage descriptions:** hide time-learning skill lines when Time is off. Several descriptions combine traversal and curricular text; split these so schedules/time-language claims disappear without deleting useful gameplay directions. In mixed mode, label time skills as the Time portion and show a separate selected-practice summary.
- **Gate UI:** “WORK WITH TIME”, “MOVE THROUGH TIME”, clock controls, AM/PM/day fields, time-unit errors and landmark-hop methods must be used only by relevant Time tasks. Use “FIND THE MISSING NUMBER” and “MATH GATE” for subtraction.
- **Practice Relay:** preserve five challenges; use only adult-enabled subjects/types/range. Remove the unprotected practice-math selector as a way to expand the adult selection. Children may choose a subset of allowed practice, never a disabled subject. Keep Time skill options available when Time is enabled.
- **Narration:** speak equations as “blank minus seven equals twelve”; speak stories naturally; never announce an unrevealed answer.
- **Reports:** replace “completed time challenges” with “completed challenges”; group by subject and stable type ID. Retain all historical records. Keep the four subtraction types separate so equations cannot conceal word-problem difficulty.
- **Evidence:** subtraction has no noon/midnight boundary flags. Use an empty legacy boundary array for compatibility. Preserve support/attempt distinctions. The existing weighted score is a support-weighted practice indicator, not a new accuracy percentage; label it clearly. Do not apply time-boundary mastery requirements to subtraction.
- **Theme:** retain title, clocks, clockwork art, TIME interaction control, time-slowing powers, music and narrative. These are gameplay features, not curriculum promises.
- **No MCQ:** apply to both enabled subjects. Existing word-time choice buttons and route-answer selection lists must become entered responses. For route questions allow typed identifiers and explicitly stated NONE/EQUAL vocabulary; AM/PM and answer-unit controls are representation selectors, not supplied solution choices. Preserve the underlying Time constructs. This is an explicit change to existing Time answer presentation.

## 8. Instructional modes
Preserve the four modes and stage overrides. Apply their existing progression policy through module-specific content:
- **Teach:** worked example first; earn credit by answering a fresh check.
- **Guide:** hints on incorrect responses; after four failed attempts, demonstrate, then require a fresh correct check.
- **Independent:** entered response, neutral feedback, no automatic reveal; correct answer earns credit.
- **Mastery:** no automatic reveal; require two consecutive correct responses across distinct same-type items. A wrong response resets the first-success condition.

Revealing an answer never credits that item. Subtraction hints explain the unknown’s role and inverse operation; do not mention units of time or days. Keep mode-specific scoring/support semantics consistent with the full accepted answer-mode specification; resolve any source/spec discrepancy before changing it.

## 9. Saves, import and compatibility
Keep chrono-circuit-save-v1 and legacy numeric room meanings. Increment the internal save schema from 5 to 6. Retain migration support for 1–5.
- Missing modular configuration in old saves means legacy Time; reconstruct old pending questions with the legacy generator.
- Store generator version, run seed and immutable math configuration per route. Store equivalent metadata for an active relay if resuming it is supported.
- New IDs include stage ownership, run and module/type identities to prevent cross-subject credits and collisions.
- Preserve credited work, drafts, checks, powers, clears, checkpoints and records through valid roundtrips.
- Validate bounded integer ranges, known IDs and configuration structure explicitly. Existing numeric-settings migration clamps some values to 0–1; new range fields must not use that path.
- Reconstruct imported items from canonical metadata; do not trust supplied answers. Discard an invalid learning entry without destroying unrelated valid progress.
- Preserve current adult configuration during progress import, matching the existing answer-mode protection policy. Imported active runs retain their validated snapshot and are labeled clearly.
- Old records lacking moduleId are Time records; do not relabel them Subtraction.
- No silent data wipe or automatic restart to apply a subject change.
